## What is implemented

- Expiry and write authorization apply to entries, notes, attached images, reservations and file delivery. Private notes belong to their author; there is no recipient passcode unlock flow.
- New rooms support open four-digit codes and opaque invitation links. Owners can change the code, close code joining, set an optional deadline, or revoke all recipient grants and issue a replacement link. Existing rooms retain their prior access and expiry settings until their owner updates them.
- Ownership recovery transfers the former owner's content, replaces the recovery key, and has a separate `/recover` page. Account linking preserves the anonymous user ID; existing-account sign-in uses a short-lived proof to transfer owned rooms.
- Optional verified sender accounts, dashboard, account/billing pages, named handoff rooms, welcome instructions, read-only recipients and one reusable settings template. Time limits are available on Free and Pro; saved handoff templates can apply a 7/30-day default.
- The free project-handoff entry point creates a room with no deadline and an editable handoff checklist. Pro adds its saved settings. Recipients remain account-free.
- $8/month Pro checkout review and completion screens, hosted payment, provider portal route, signed webhooks, an event ledger, current-state reconciliation and capacity admission for at most five paid pilot accounts. Actual no-charge provider purchase and signed delivery passed in isolation on October 9. The provider portal remains blocked by store activation, and live checkout remains off.
- Help, pricing and freelance handoff pages; distinct utility pages; blog corrections and three focused guides; consistent existing orange theme, dark/light styles, accessible navigation and private-page indexing exclusions.
- Each file request is authorized through the viewer's room and asset RLS. New uploads use `cacheControl: "0"`; only backend metadata reporting `max-age=0` or `no-store` permits a direct Storage redirect with a token lifetime bounded by room/file deadlines and capped at 60 seconds. Legacy, long-cache or unknown-cache objects stream through the authenticated application route with `private, no-store`, without exposing another signed Storage URL. Token expiry and response cache lifetime are independent; earlier cached responses and downloaded copies cannot be recalled by changing RLS. [Supabase signed URLs and caching](https://supabase.com/docs/guides/storage/cdn/smart-cdn#signed-urls-and-cdn-caching).
- Native browser Print / Save as PDF for individual notes, and HTML exports with embedded images in ZIPs. Large archives stop at a 128 MiB browser byte budget. Remote images that cannot be fetched cause export to fail visibly, rather than silently dropping images.
- Third-party analytics scripts are disabled. Private daily aggregate counters record successful creation/publication and authorized share/download initiation or upload failure. They contain no room codes, filenames, invitation tokens or note text. Download initiation is not download completion.
